# GSun — фабрика PR, V1

Дата: 23.10.2026. Статус: конфигурация и черновики, не работающий сервис. Публикаций и отправок нет. План продолжает GSun-Communications-Investor-Plan-V1 от 23.10; сроки того плана были ориентирами. Конфигурация factory.config.json пока не подключена к исполняющему приложению.

## Результат первой итерации

Один подтверждённый материал превращается в статью/заметку и адаптированные RU/EN посты. До публикации владелец утверждает точный текст, изображения, канал и время. Изменение текста отменяет старое согласование. В первый запуск достаточно одного канала. Никаких выдуманных новостей ради регулярности.

Три аудитории: владельцы станций (услуги и реальные объекты), инженеры (проверенные возможности и ограничения), партнёры/инвесторы (этапы, доказательства и конкретные задачи). Для каждой — отдельный призыв к действию. Готовность Oracle, MRV, сертификатов и патентов нельзя выводить из маркетинговых формулировок или тестового прогона.

## Проверка каналов

- Telegram: официальный Bot API поддерживает отправку в канал; нужны целевой канал и права публикации у бота. Известный @greensun_energy_bot — контактный бот, не подтверждённый новостной канал. Источник: https://core.telegram.org/bots/api#sendmessage .
- MAX: POST /messages поддерживает чат/канал, нужен chat_id и авторизация бота с правами. Ссылка приглашения владельца сама по себе не устанавливает тип ресурса и доступ. Источники: https://dev.max.ru/docs-api/methods/POST/messages и https://dev.max.ru/docs-api/use-cases/bot-in-chats-and-channels . Перед реализацией сверить актуальные endpoint, TLS и ограничения.
- Metricool: 23.10 подключение getBrandSettings ответило, что у бренда нет подключённых соцсетей. Публикация и аналитика не настроены. Не считать наличие инструмента действующим каналом. Подключение выполняет владелец в своём кабинете; цену и состав нужного тарифа ещё не проверяли.
- VK: официальный SDK содержит wall.post; реальное сообщество, токен, права и условия конкретного приложения не проверены. Источник: https://github.com/VKCOM/vk-php-sdk/blob/master/src/VK/Actions/Wall.php . Следующий этап, не подключённый канал.
- LinkedIn/X: кандидаты для англоязычного направления; аккаунты, тарифы, региональные условия и права публикации не проверены.
- Сайт: нужен утверждённый раздел новостей; публикация статьи должна предшествовать соцсетям, если пост ссылается на неё. greensun.energy — объекты/услуги, gsun.ai — продукт и развитие. /start остаётся входом с QR.
- Polygon, Giveth и каталоги: адресная ручная подача с проверкой правил и точного профиля проекта. Не использовать массовую автопубликацию. Пост на форуме не означает партнёрство.

## Поток и хранение

Источник → проверка фактов → черновик RU/EN → адаптация площадки → согласование → очередь → публикация → URL/ID результата → метрики.

В публичном Git допустимы только публичные материалы, обезличенные шаблоны и инструкции. Частные документы пилота, персональные данные и секреты туда не копировать. В PR не включать неопубликованные коммерчески чувствительные планы. На сервере будущий исполнитель должен быть отдельным сервисом, без прав управления Oracle/инверторами. Провайдер генерации выбирается отдельно; локальная модель допустима, но ещё не подключена.

Источник каждого утверждения должен иметь URL, дату проверки, статус «выпущено / проверено в пилоте / план / заявление». Для фото — происхождение и разрешение; синтетические изображения не выдавать за реальные объекты. Перевод EN не должен усиливать обещания RU.

Защита от повторов: ключ материала+канала+языка+хеша. После неопределённого ответа API не отправлять повторно вслепую: сначала сверить факт публикации. Логировать состояние, remote_id и публичную ссылку без токенов. Кнопка/флаг остановки обязательны. Ошибки одного канала не должны повторять уже опубликованное в другом.

## Порядок подключения

1. Владелец указывает публичный новостной канал Telegram (не контактного бота) и подтверждает, какой ресурс MAX является каналом. Для Metricool владелец подключает выбранную соцсеть; наличие учётной записи не означает необходимость покупки тарифа.
2. Настроить секреты на целевой машине без передачи в чат/Git, проверить доступ к назначенному каналу чтением, отдельно проверить права.
3. Реализовать исполнитель сначала в режиме dry-run; проверить запрет без согласования, отмену согласования после правки и защиту от дублей.
4. Владелец утверждает один конкретный тестовый пост и назначение; выполнить отправку и проверить опубликованный результат. Только затем включать регулярную очередь.

Метрики: переходы с UTM без персональных данных, заявки, запросы демонстрации, квалифицированные партнёрские обращения. Не обещать немедленную индексацию. Хэштеги — тематическое оформление, не замена содержанию и индексации.

Критерий готовности V1: один материал прошёл проверку и согласование, опубликован в одном выбранном канале, сохранены ID/URL, повторный запуск не создаёт дубль. На 23.10.2026 этот критерий НЕ ДОСТИГНУТ.
