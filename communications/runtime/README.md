# GSun PR runtime — кандидат V1

23.10.2026. Код подготовлен и проверен локально; на VPS не установлен. Ручная приветственная публикация успешна со слов владельца; ID сообщения ещё не сверяли. Это уточняет устаревший blocker в родительском factory.config.json. Этот runtime пока не читает тот конфигурационный файл.

## Согласованный режим

- Telegram @Gsun_ai, bot @greensun_energy_bot, chat_id -1004428833073.
- Понедельник, среда, пятница, 11:00 Europe/Moscow.
- Владелец один раз согласует весь месячный пакет. Изменение пакета аннулирует согласование.
- Предложенные напоминания: за 24 часа и за час, в личный Telegram владельца.
- RU публикуется; EN сохраняется в плане для дальнейшего использования.

## Что работает в коде

Месячный календарь; генерация RU/EN и задания на иллюстрацию через chat-completions-совместимый API; отдельный модельный редактор; проверка структуры, длины, ссылок, актуальности и хешей базы фактов; привязка согласования к точному пакету; отправка текста или фотографии; SQLite-журнал; защита от повторной отправки; локальная блокировка параллельных запусков; личные напоминания; PAUSE.

Факты предварительно проверяет человек: runtime не открывает источники и не доказывает истинность утверждений. Модельный редактор также может ошибаться. Результаты испытаний, планы и доступные услуги должны быть различимы в исходных фактах и согласованных текстах.

Автоматическая генерация самих изображений ещё не подключена. Доступны собственные фотографии и заранее подготовленные иллюстрации из локального каталога. Нужны подтверждённые права; иллюстрации маркируются. MAX и другие сети пока не реализованы. Живые вызовы LLM и отправка этим runtime ещё не проверены; 16 тестов используют подмены внешних сервисов.

## Подготовка на VPS

Нужны Linux, Python >=3.9 с zoneinfo и базой часовых поясов, рабочий пользовательский systemd. Сначала проверить поддержку sandbox-настроек unit-файлов и запуск user services после выхода из SSH. Не менять работающий сайт или webhook существующего бота.

Разместить код в ~/gsun-pr, конфигурацию в ~/.config/gsun-pr/runtime.env (права 0600), состояние в ~/.local/share/gsun-pr (0700). Всё вне webroot. Секреты не помещать в GitHub или сообщения чата.

runtime.env.example содержит имена переменных. Выбрать провайдера, точный endpoint /chat/completions, модель и бюджет; ключ вводить только на сервере. REVIEW_* позволяет подключить отдельную модель проверки. Если не задано — используется отдельный вызов основной модели. OWNER_CHAT_ID должен быть числовым ID личного чата владельца; владелец предварительно открывает бота. Код не вызывает getUpdates и не изменяет webhook.

Скопировать facts.example.json в каталог состояния как facts.json и заполнить проверенными публичными фактами с source_url, checked_at и valid_until. Пример специально не допускает публикацию. Нужно минимум три допустимых факта, действующих до последнего поста месяца. media.json — словарь ресурсов; допустим пустой {}.

Фотографии JPEG/PNG положить в assets внутри каталога состояния. Для каждого ресурса в media.json указать path относительно assets, sha256, rights_confirmed:true, kind:photo или illustration. Хеш можно получить sha256sum. Размер до 10 МБ; параметры изображения дополнительно проверить пробной отправкой до месячного согласования. Для иллюстрации подпись содержит слово «Иллюстрация».

После безопасной загрузки переменных окружения выполнить:

```sh
python3 ~/gsun-pr/factory.py check-telegram
python3 ~/gsun-pr/factory.py generate 2026-11
python3 ~/gsun-pr/factory.py inspect 2026-11
```

Просмотреть все тексты, факты и изображения. Команда inspect выводит APPROVAL_HASH. Затем согласовать именно этот хеш:

```sh
python3 ~/gsun-pr/factory.py approve 2026-11 --hash HASH_FROM_INSPECT
python3 ~/gsun-pr/factory.py tick
```

Последняя команда — dry run. Для действительной отправки нужны GSUN_PUBLISH_ENABLED=yes и tick --live. Включать timer только после проверки конфигурации и согласования пакета. GSUN_GENERATE_ENABLED=yes разрешает prepare-next; предложенный таймер создаёт пакет следующего месяца 25-го числа в 10:00 МСК. Самостоятельно пакет не согласует. Новое создание отражается в журнале systemd, отдельного уведомления о готовности пакета пока нет.

Unit-файлы предназначены для ~/.config/systemd/user. До enable проверить пути, доступ и systemd-analyze verify. Состояние сохранять при обновлениях кода; не сбрасывать deliveries SQLite. Не включать таймеры одновременно на двух серверах.

## Операционная работа

Создание ~/.local/share/gsun-pr/PAUSE останавливает отправки и напоминания. Для полного отключения остановить оба timer. Логи: journalctl --user -u gsun-pr.service и -u gsun-pr-prepare.service.

Отправка резервируется в журнале до сетевого запроса. При неизвестном результате автоматического повтора нет: оператор проверяет канал, сопоставляет сообщение и журнал. Даже явную ошибку API эта версия автоматически не повторяет. Это предотвращает дубли, но требует ручного восстановления пропущенной отправки.

Пост старше 15 минут не догоняется автоматически: владельцу отправляется уведомление. Напоминания также имеют 15-минутное окно; длительный простой может привести к их пропуску. PAUSE, недоступность API или неверная конфигурация не гарантируют доставку уведомлений. Мониторинг доступности процесса — отдельный следующий шаг.

Проверка: python3 -m unittest -q test_factory.py (16 локальных тестов). До промышленного запуска обязательны пробный пакет, реальная доставка фото и уведомления, проверка перезапуска и сверка журнала. Генерация изображений, лимиты расходов провайдера и остальные социальные сети остаются следующими интеграциями.

## Закрытый кабинет (дополнение 23.10.2026)

Добавлены bridge.py, gsun-pr-bridge.service и install.sh. Bridge слушает только 127.0.0.1:8791; каждый запрос требует Bearer GSUN_PR_BRIDGE_TOKEN (минимум 32 символа). Через него доступны предпросмотр, медиа, согласование точного хеша и PAUSE/resume. Все операции используют общий fcntl lock с publisher. HTTP-запросы не запускают генерацию и не отправляют пост немедленно.

Установка из проверенной версии: sh communications/runtime/install.sh. Существующая установка или unit вызывают STOP; конфигурация и состояние не заменяются. Ничего не запускается автоматически. Владелец подтвердил Python 3.12.3, systemd user running, Linger=yes.

Для связи с Worker нужен отдельный HTTPS-маршрут существующего reverse proxy к loopback. Сначала инвентаризация конфигурации, затем точечное изменение и проверка. Не открывать 8791 наружу. Worker vars: GSUN_PUBLICATIONS_OWNER_USER_ID, GSUN_PR_BRIDGE_URL; secret: GSUN_PR_BRIDGE_TOKEN. Ключ совпадает с приватным env VPS, генерируется и сохраняется локально; не передавать через чат. Настройки сайта/Oracle не менять ради этого маршрута.

UI не показывает heartbeat: publish_enabled отражает только env-флаг. Тексты и медиа пока редактируются локально до повторной проверки/согласования. Время напоминаний в UI расчётное; delivery — состояние отправки поста из SQLite. Live-проверка всей цепи и браузерная проверка ещё впереди. 21 тест Python (16 очереди + 5 bridge) прошли локально.

## Возобновляемая генерация — 24.10.2026

После успешного короткого REST-теста владельца (8,3 с, JSON RU/EN) генерация месяца заменена на последовательные запросы по одному посту. Каждый структурно допустимый пост атомарно сохраняется в generation/YYYY-MM.json. Повторный generate продолжает с сохранённого количества. Изменение фактов, медиа, модели или endpoint блокирует повторное использование checkpoint; без ручной сверки его удалять нельзя. После всех постов выполняется отдельная проверка всего пакета; итоговый plans/YYYY-MM.json по-прежнему не согласован автоматически. Частичные checkpoints не являются публикационной очередью. Модельная проверка не заменяет проверку владельцем.

Для api.cloudflare.com используются max_completion_tokens=2400 и reasoning_effort=low; для других провайдеров max_tokens=2400. Обрезанные ответы отклоняются. HTTP-код, тайм-аут и сетевая ошибка различаются без вывода секретов или тела ответа. Автоматических повторов сетевых запросов нет. Причина прежнего REMOTE_REQUEST_FAILED не установлена ретроспективно; работа полного месяца после изменения требует проверки на VPS. 41 выполненная проверка unittest прошла локально (включая повторно импортированные тесты очереди).
