## Инцидент SSH, 23.10.2026

Команда из исторических записей на Mac владельца вернула:

```text
PTY allocation request failed on channel 0
SSH-2.0-OpenSSH_10.0p2 Debian-7
```

Факт: обычное приглашение shell не получено. Баннер SSH после отказа PTY не доказывает, к какому конечному shell ведёт соединение. Возможны ограничения ключа/команды либо особенности маршрутизации; причина пока НЕ УСТАНОВЛЕНА. Не исправлять это слепым добавлением -tt, отключением проверки ключа сервера или изменением sshd.

Из среды ассистента отдельная попытка ранее завершилась Network is unreachable до аутентификации. Это другое наблюдение, не причина отказа на Mac.

Следующая проверка — локально посмотреть эффективные SSH-настройки через ssh -G, выбрав только hostname, user, port, requesttty, sessiontype, identitiesonly и identityfile. Команда не соединяется с сервером. ProxyCommand/RemoteCommand проверять локально отдельно; не публиковать их без проверки на секреты. После установления рабочего способа записать безопасный alias и дату успешного чтения hostname/pwd, не публикуя ключи.

## Правила продолжения

1. Установить ресурс и задачу, проверить актуальный статус доступа.
2. Отличать доступ владельца с Mac от доступа инструментов ИИ. История успешного входа не заменяет текущую проверку.
3. Для сайта сначала прочитать текущие файлы, сверить Git и резервную копию; затем готовить отдельный PR.
4. Для каждого нового способа доступа записывать место выполнения, назначение учётной записи, ограничения, дату проверки и результат. Секреты хранить вне Git.
5. Документ находится в Draft PR до слияния: искать в ветке docs/site-inventory-20261023. После слияния читать из main.
