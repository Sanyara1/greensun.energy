## Инцидент SSH, 23.10.2026

Команда из исторических записей на Mac владельца вернула:

```text
PTY allocation request failed on channel 0
SSH-2.0-OpenSSH_10.0p2 Debian-7
```

Факт: обычное приглашение shell не получено. Баннер SSH после отказа PTY не доказывает, к какому конечному shell ведёт соединение. Возможны ограничения ключа/команды либо особенности маршрутизации; причина пока НЕ УСТАНОВЛЕНА. Не исправлять это слепым добавлением -tt, отключением проверки ключа сервера или изменением sshd.

Из среды ассистента отдельная попытка ранее завершилась Network is unreachable до аутентификации. Это другое наблюдение, не причина отказа на Mac.

## Подтверждённый вход с Mac, 23.10.2026

Владелец выполнил в локальном терминале Mac:

```bash
ssh -o PubkeyAuthentication=no -o PreferredAuthentications=password -o ConnectTimeout=15 tunnel@109.196.165.108
```

Пароль вводится только в запрос терминала. Пароль и ключи в документ не записываются. Параметры действуют для одного запуска; SSH-конфигурация не изменялась.

После подключения владелец выполнил:

```bash
whoami
hostname
pwd
```

Подтверждённый вывод:

```text
tunnel
wgctmstpsf
/home/tunnel
```

Источник подтверждения: вывод терминала, присланный владельцем 23.10.2026. Интерактивный shell по паролю работает с Mac. Права sudo, содержимое /var/www/greensun.energy и соответствие GitHub ещё не проверены. Это не подтверждает прямой SSH-доступ из среды ассистента.

Проверка ssh -G перед входом показала: user=tunnel, hostname=109.196.165.108, port=22, identitiesonly=no, requesttty=auto, sessiontype=default и стандартные identityfile. Ранее предложенные ключи могли иметь ограничения; точный принятый ключ и серверная причина отказа PTY не установлены. Не удалять ключи и не менять ограничения на основании этой гипотезы.

При входе сервер сообщил System restart required. Это только наблюдение; перезагрузка не выполнялась и этой записью не разрешается.

## Правила продолжения

1. Установить ресурс и задачу, проверить актуальный статус доступа.
2. Отличать доступ владельца с Mac от доступа инструментов ИИ. История успешного входа не заменяет текущую проверку.
3. Для сайта сначала прочитать текущие файлы, сверить Git и резервную копию; затем готовить отдельный PR.
4. Для каждого нового способа доступа записывать место выполнения, назначение учётной записи, ограничения, дату проверки и результат. Секреты хранить вне Git.
5. Документ находится в Draft PR до слияния: искать в ветке docs/site-inventory-20261023. После слияния читать из main.
